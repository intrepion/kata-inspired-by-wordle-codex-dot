# Automatic inline meanings for displayed words

The user requested definitions in place without Define buttons or an online-lookup step, and a definition for each guess. This explicitly authorizes automatic individual-word requests for rendered guesses, current advice suggestions and disclosed terminal answers. The only source remains Wiktionary’s English experimental structured endpoint and CC BY-SA4.0 content, as documented in ADR0011. No account, payment, dataset redistribution or new service is introduced.

Submitted rows keep their five-tile feedback and receive a concise meaning immediately below. Advice/result entries include their own meaning. Loading, no-English-entry, offline/unavailable and timeout messages are honest; accepted membership never depends on lookup success. A native More senses disclosure expands additional senses and parts of speech. Text is inserted through textContent/text nodes, never HTML. Every meaning has its fixed-source link; the nearby common disclosure gives attribution/license, automatic request scope and network privacy. Source links use no-referrer/noopener. No hidden answer or undisplayed candidate is queued. Reloaded guesses are eligible without changing save schema3, so this update causes no additional reset.

InlineDefinitions owns the currently rendered set, bounded to17 unique five-letter words (six guesses, ten suggestions, one revealed answer). It debounces180ms, runs at most two requests, shares duplicate requests/cache, and cancels removed words. Tokens reject delayed stale completions even if transport ignores cancellation. The existing client bounds/cleans responses and times out after6s. Success/missing cache remains64 entries with24h/5min TTL; errors remain visible without repeated render/typing retries. Reload retries unavailable entries, and the client cache is tab-memory only. No background retry loop or bulk dictionary fetch. Results update only the matching inline nodes, without rebuilding the game/keyboard. Mode/advice changes remove stale slots; keyboard activation of summary/source links stays native and never submits a guess.

TDD seams are the public visible-word queue/client boundary and browser game interactions requested in the handoff. The automatic-fetch test failed before implementation; a second red test proved cached words must publish immediately when rendered. Public-seam tests cover two-request limit, duplicate words, cached completion, cancellation, late responses, missing/offline/invalid/timeout outcomes, no repeated failure retries, debounce and visible-word normalization. Browser boundary fixtures exercise all six guesses/reloads, suggestions, final answer deduplication, no hidden requests, source markup safety, typing and native expansion. Existing scoring/persistence/advice tests remain unchanged.


Independent review found focus could be lost when a cached definition or board was re-rendered. A browser regression reproduced the loss before the fix. Summary/source-link identity is now captured and restored to the matching visible occurrence, with an active-mode fallback if removed. Native Enter on summary/source links remains separate from submitting a guess. The disclosure explicitly says the provider can see/correlate the individually requested words and IP address; no puzzle identifiers, drafts, hidden answers or saved statistics are sent.
